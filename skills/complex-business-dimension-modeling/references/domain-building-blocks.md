# 领域构件（DDD 战术构件）

只覆盖**战术构件**：值对象、实体、聚合、领域服务、工厂、仓储。

**战略设计（限界上下文、子域、上下文映射、团队边界）不在此**——那是架构 / 组织层的事，与本 skill 无关。

本 skill 把这些构件当作**既有地基**：它不负责构件怎么建，但**构件建错，上面的决策维度就没有落脚点**。所以做新需求、要划构件时，读本文件。

## 1. 值对象

判据：

```text
没有身份标识，靠「值相等」判断是不是同一个；
不可变——「改」就是换一个新的。
```

适合：`Money` / `Address` / `DateRange` / `PhoneNumber`。

反例：如果它需要被**单独查询、单独修改、有独立生命周期** → 它是实体，不是值对象。

```go
type Money struct {
    amount   int64  // 私有，不给外部改
    currency string
}

func (m Money) Add(other Money) (Money, error) {
    if m.currency != other.currency {
        return Money{}, errors.New("币种不一致")
    }
    return Money{m.amount + other.amount, m.currency}, nil
}
```

## 2. 实体

判据：

```text
有唯一标识（ID），生命周期内 ID 不变、其他属性可变；
承载自己的不变量。
```

**放 Entity 的：**

| 放什么 | 例 |
|---|---|
| 身份 | 订单号、用户 ID |
| 自身状态 | `Status` |
| 自身不变量所需的事实 | 明细、总额 |
| 只依赖自身的查询 | `IsPaid()`、`Total()` |
| 维护自身不变量 / 生命周期的行为 | `AddLineItem()`、`Pay()` |

**不放 Entity 的：**

| 不放什么 | 为什么 |
|---|---|
| 能否用券 | 依赖会员 / 地区 / 活动 → 是决策点的事 |
| 税怎么算 | 依赖地区 / 税类 + 算法 → 是决策点的事 |
| 只在某场景成立的判断 | 约束在决策点 |

一句话：**决策逻辑不进 Entity。**

判断归属只看三个字——**依赖谁**：只依赖自己 → Entity；依赖别人 / 配置 / 时间 → 那个决策点。**名字像谁的事，不算数。**

> **DB 信息 → Entity 是翻译，不是搬运。**
> 业务事实进；技术元数据（`created_at` / `version` / `tenant_id`）可留在持久层；派生值做成方法不存。
> 取舍标准只有一条：**决策需要的事实，必须能通过 Entity 取到。**

## 3. 聚合

判据（核心是**一致性边界**）：

```text
这些东西是不是必须「同时正确」？
    必须           → 同一个聚合
    可以短暂不一致  → 不同聚合，用领域事件 / 最终一致收
```

规则：

- **一个事务只改一个聚合**；
- 聚合根是唯一入口，外部只能持有根的 **ID**，不持有内部对象引用；
- 聚合**宜小不宜大**——大聚合 = 锁竞争 + 事务长。

反例：为省事把一堆对象塞进一个聚合 → 并发退化、锁冲突。

## 4. 领域服务

判据：

```text
一个操作跨多个实体 / 值对象，且不属于任何单一对象的天然职责 → 领域服务；
否则 → 优先放实体方法（充血模型）。
```

反例：把实体该有的行为搬进 Service（贫血模型）。

> 判断 / 计算 / 分发类逻辑，本 skill 有专门判据，见 `pattern-selection.md`；DDD 会把它算作领域服务的一种。**同层，别两处都写。**

---

## 5. 工厂

判据：

```text
构造逻辑复杂（多步、有条件、需组装）；
或必须「成套」提供 → ProductTypeModule / 抽象工厂，见 pattern-selection.md §9。
否则 → 普通构造函数。
```

---

## 6. 仓储

判据：

```text
按聚合为单位：一个聚合一个仓储；
返回领域对象，不返回表行 / DTO；
负责 DB ↔ Entity 的翻译（映射、重建）。
```

反例：为每张表建一个仓储；仓储里塞业务规则或复杂查询。

---

## 7. 速查

| 遇到 | 用 |
|---|---|
| 一段无标识、不可变的值 | 值对象 |
| 有 ID、有生命周期、有不变量 | 实体 |
| 几个对象必须同时正确 | 一个聚合 |
| 跨对象的领域操作 | 领域服务 |
| 构造复杂 / 成套 | 工厂 |
| 持久化 / 重建对象 | 仓储 |
| **判断 / 计算 / 分发** | **去 `pattern-selection.md`**（Rule / Policy / Config / Strategy） |
